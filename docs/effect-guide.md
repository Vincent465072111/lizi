# 粒子记忆效果学习卡

依据：用户提供的视频 7621414148248726137.mp4，时长约 5 分 2 秒。分析依据为视频画面、字幕、交互过程和参数面板。下文的技术方案是可用于实现类似效果的建议，不能据此确定原作者的源码、算法或服务配置。视频末尾的教学提示词仅作为素材内容理解。

## 1. 一句话描述

黑色背景中，照片以彩色粒子的形式悬浮；主体保持可辨认，边缘逐渐化为细小颗粒；粒子缓慢流动、产生空间扭转，并对鼠标和声音作出反应。产品将它用作照片聊天、日记生成和记忆相册的视觉载体。

## 3. 效果词典：把感觉改写成可执行要求

| 日常说法 | 可用术语 | 告诉 AI 做什么 |
| --- | --- | --- |
| 照片变成很多点 | 图片粒子化 / Image-based particles | 根据照片位置采样颜色，再用彩色点重新组成照片 |
| 边缘像烟一样散掉 | 粒子消散 / Particle dispersion；柔边遮罩 / Soft mask | 中心密集，越靠边越稀疏、越透明，打散矩形轮廓 |
| 像一阵风吹动 | 流场 / Flow field；噪声扰动 / Noise displacement | 让附近的点按连续规律一起运动，避免每个点独立乱抖 |
| 照片有起伏和厚度 | 深度位移 / Depth displacement | 让点在前后方向也发生少量位移 |
| 转起来像薄薄的布 | 空间旋转、透视、形变 | 将照片看作可变形的薄片，在空间中旋转并弯曲 |
| 鼠标附近被推开 | 鼠标排斥 / Pointer repulsion | 鼠标半径内的点向外移动，越近越强，移开后平滑复位 |
| 像一个小黑洞 | 局部扭曲 / Local distortion | 描述希望看到的空洞、亮边、吸引或排斥方向；不必要求真实物理黑洞 |
| 亮处柔柔发光 | 柔光 / Glow；泛光 / Bloom | 只让高亮区域产生适量光晕，保留照片细节 |
| 声音越响动得越大 | 音频响应 / Audio-reactive | 将所选音源的音量或频段强度映射到位移幅度，并平滑变化 |
| 切换时像飘到下一张 | 空间轮播 / Spatial carousel；缓动 / Easing | 同时调整位置、角度和缩放，让动画起止平滑 |

注意：图片整体可能完全由粒子组成，也可能由连续图片和粒子边缘叠加而成。视频不能唯一确定是哪一种。若追求主体清晰，可以明确要求“照片主体清晰，主要在边缘呈现颗粒感”。

## 4. 视频中确实出现的旋钮

| 面板字段 | 小白理解 | 数值增大的预期变化 |
| --- | --- | --- |
| DISPERSION | 散开程度 | 粒子离原位置更远，轮廓更松散 |
| PARTICLE SIZE | 每个点有多大 | 颗粒更明显，也更容易互相覆盖 |
| CONTRAST | 明暗反差 | 明暗区别更强，过大可能丢失细节 |
| FLOW SPEED | 流动快慢 | 相同运动更快发生 |
| FLOW AMPLITUDE | 流动幅度 | 摆动距离更大 |
| DEPTH STRENGTH | 前后起伏强度 | 空间层次更明显 |
| MOUSE RADIUS | 鼠标影响范围 | 更大一片区域受影响 |
| COLOR SHIFT SPEED | 颜色变化快慢 | 颜色漂移得更快 |
| AUDIO DANCE | 是否随声音运动 | 开关音频驱动 |
| DANCE STRENGTH | 声音带来的动作强度 | 同样音量下动作更明显 |
| DEPTH WAVE | 深度方向的波动 | 通常表示前后起伏的波动程度，确切定义需看代码 |

字段值的单位和范围由代码定义。另一个项目里的“1.5”未必等于这里的“1.5”。沟通时优先说可观察变化，例如“幅度减半”或“影响照片宽度约 15% 的区域”。

最容易混淆的两组：速度决定“动得快不快”，幅度决定“动得远不远”；鼠标半径决定“影响多少点”，排斥强度决定“推得多远”。

## 5. 一个粒子如何工作

可以把照片想成一幅由彩色小珠子拼成的画。每颗珠子保留三类信息：原来的位置、原来的颜色、当前的位置。

当前位置由几部分共同决定：原位置 + 平时的流动偏移 + 鼠标产生的偏移 + 声音产生的偏移。为了保持照片可辨认，需要限制偏移幅度，或让粒子逐渐回到原位。平滑规律让相邻粒子像被同一阵风吹动；完全独立的随机位置更容易形成杂乱闪烁。

这是一种概念模型，不代表作者的精确公式。仅为制造这种空间感，不一定需要把原照片重建成完整的三维场景。

## 6. 产品能力与视觉效果

用户流程可以写成：上传照片 → 围绕照片聊天 → 结束并整理日记 → 保存照片和日记 → 从相册重新查看。

制作时可以分成三层：

1. 视觉层：照片、粒子、形变、鼠标、动效。可以先用固定图片和模拟声音做出原型。
2. 交互层：上传、麦克风按钮、文字显示、生成中、错误重试、相册切换。
3. 能力与数据层：真实语音会话、照片理解、日记生成，以及照片和日记的保存及关联。

按钮和对话动画出现，并不等于真实模型或保存能力已经接通。验收时分别检查“看起来对”与“功能确实可用”。

## 7. 通用表达模板

对象 + 外观 + 触发条件 + 变化方式 + 时间与幅度 + 恢复方式。

例如：鼠标靠近照片时，以指针为中心、约照片宽度 15% 的范围内，粒子向外推开。越靠近中心，推开的距离越大。鼠标移开后，大约 0.8 秒平滑回到原位。照片主体始终可以辨认。

以上比例与时间是起步示例，未经视频测量。

可填写的效果规格卡：

- 使用场景：我的什么产品，在哪个页面出现。
- 参考位置：视频第几秒到第几秒，关注哪一个效果。
- 对象：照片、文字、按钮、卡片还是整个场景。
- 静止外观：颜色、大小、材质、位置、清晰程度。
- 触发方式：自动、鼠标移动、点击、滚动、触摸还是声音。
- 变化过程：哪个属性改变，方向是什么，谁先动谁后动。
- 节奏与幅度：快慢、距离、角度、停留时间。
- 结束状态：保持、复位、切到下一张还是消失。
- 可调参数：希望通过哪些旋钮反复试。
- 验收标准：我如何判断成功，手机上如何操作。

## 8. 可复制给 AI 的起步提示词

```text
我想做一个用于照片日记产品的“粒子照片”交互原型。
参考我提供的视频，重点参考前 35 秒的照片粒子效果。

视觉：
- 黑色背景，照片悬浮在画面中央，周围保留大量空白。
- 主体保持可辨认，保留照片原有颜色。
- 粒子细小密集，边缘逐渐变稀疏、透明，并形成不规则轮廓。
- 粒子有缓慢、连续的流动，相邻区域运动有连贯性。
- 增加轻微前后起伏与空间倾斜，先保证主体清晰。

交互：
- 鼠标靠近时，附近粒子产生局部排斥，越近越强。
- 起步影响半径设为照片宽度约 15%，移开后约 0.8 秒平滑恢复。
- 手机支持触摸触发相同反馈。

调参：
提供粒子大小、散开程度、流动速度、流动幅度、深度强度、
鼠标影响范围和排斥强度的调节项。
参数用中文解释，让我能够理解增大或减小时的变化。

交付顺序：
先完成单张照片的可运行视觉原型，并给出运行方法。
验证照片可辨认、鼠标反馈连续、手机能操作后，
再扩展多张照片切换、音频响应和真实 AI 日记功能。

技术可以考虑 Three.js 的点云与自定义 Shader。
如果采用更简单的方案，请说明它能做到什么、哪些视觉差异会保留。
我给出的比例与时间是可调整的初始设定，不是视频实测值。
```

## 9. 迭代时这样说

- “流动速度保持不变，把摆动幅度减半，让照片更容易看清。”
- “主体区域更密集，只让边缘大约四分之一的区域明显散开。”
- “鼠标影响范围保持不变，把推开距离减小，复位过程放慢一些。”
- “相册切换保留左右移动，把旋转角度减少，减少眩晕感。”
- “声音变大时主要改变边缘起伏，不要让整张照片剧烈跳动。”

每轮保留一个满意版本，只修改一到两个可观察属性，再比较变化。

## 10. 技术名词只需认识这些

- WebGL：浏览器中使用图形硬件绘制二维、三维效果的一条途径。
- Three.js：帮助组织和绘制三维场景的工具，Points 可表示点云。
- Shader：运行在图形处理器上的小程序，可定义粒子如何移动和显示。
- Web Audio API / AnalyserNode：读取音频随时间变化的数据，用于声音可视化。

以上是可用的实现路径，不是对视频作者实际技术栈的认定。
